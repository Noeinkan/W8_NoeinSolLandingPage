- **`testLegacyTokenBudget` (M3).** The pre-redesign token names — `--text-primary`, `--bg-card`, `--border-subtle` and ten more — had been aliased onto the Technical Light palette so partials that still referenced them would keep rendering while M2 reworked them file by file. That block is deleted now, and this is the door closing behind it: a per-file budget shaped like `HEX_BUDGET` and `RGB_BUDGET`, except it starts empty, so the allowance is zero everywhere and any reappearance fails. It counts **declarations as well as uses**, which is the half nothing else covers: a stray `var(--text-primary)` already fails `testEveryTokenIsDefined` as an undeclared name, and the obvious way to make that failure go away is to put the alias block back — restoring exactly the drift the deletion ends, while reading to every other check as well-formed CSS with every token declared. `styles.base.css` is therefore included rather than exempt, and comments are stripped first (unlike `testColourBudget`) because the note left where the block used to be names the tokens on purpose. `--white` is on the list too, deleted an earlier milestone ago and the reason this one exists. Both branches were verified to fail before being committed green.

- **`testInkOnPaperClearsAA`.** Pairs each ink token with each paper ground and does the WCAG sum on the declared hex — pure arithmetic, no browser. The colour budgets count literals; they never read them, so a text token could ship below the AA floor with the whole suite green, and one did. Deliberately narrow: it checks the tokens against the grounds they are designed for, not every pairing a component might actually make, which is why the pass that added it also swept all 16 built pages in a real browser. Verified to fail on the value that shipped.

- **`testStylesheetsParse` (M2.4).** A stray `}` is not a parse error: the browser silently discards rules until it resynchronises, so the file still looks fine, the page still mostly works, and nothing in the suite can see it — `testEveryClassHasARule` matches class names in raw text and never asks whether the rule survived. M2.4 left exactly one behind a deleted block; it swallowed `.bep-report-header`, and the only symptom was a missing hairline under the report title. The check walks every file in `css/` with comments and quoted strings stripped and fails on a `}` arriving at depth 0 or a block left open at EOF. Counting braces would not have done: a missing open and a stray close cancel out. Both branches were verified to fail before being committed green.

- **`css/privacy.css`, and the guardrail that keeps stylesheets out of markup (M1).** Both privacy pages carried a 65-line stylesheet as a JSON-escaped string in an `inlineStyle` front-matter field — byte-for-byte identical between EN and IT — which `base.njk` poured into a `<style>` in the head. No check could see it: `testEveryClassHasARule` and `testEveryTokenIsDefined` read `css/`, and `testNoInlineStyles` matches the literal `style="`, which a JSON key never contains, so the blob sat on pre-redesign aliases through an entire visual redesign and privacy became the one page still on the old system. `testNoStylesheetsInMarkup` now fails the build on an `inlineStyle` key **or** a `<style>` tag anywhere in `src/` — pages, layout, partials and macros, because the front-matter key was only one of the two ways in. `testPrivacyPage` covers the remaining gap: drop the `css` key and leave the file, and the page renders unstyled while every other check stays green. All three branches were verified to fail before being committed green.
- **`testPageScopedClassesResolve` (M2.1).** `testEveryClassHasARule` concatenates every file in `css/`, so a class satisfies it by having a rule *somewhere* — which is not what the browser loads. A page gets `css/styles.css` plus whatever its `css` front-matter key names, and nothing else. `.page-hero-note` was declared identically in `bep-checklist.css` and `eir-checklist.css` while `builds.njk` used it and loaded neither, so the Builds hero note rendered as plain body copy for the life of the page with the suite green. The new check reads each built page's actual `<link rel="stylesheet">` hrefs, expands the `@import` manifest in `styles.css`, and resolves that page's classes against only that set. It reuses `UNSTYLED_CLASSES` and the existing JS escape hatch, and carries its own `PAGE_SCOPED_EXCEPTIONS` list that may only shrink.
